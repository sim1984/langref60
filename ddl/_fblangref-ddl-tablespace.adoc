[[fblangref-ddl-tablespace]]
= TABLESPACE

Табличные пространства используются, прежде всего, для разделения и хранения определённых объектов базы данных — таких как индексы и таблицы. Табличные пространства не имеют отношения к логической структуре базы данных, а предназначены для указания места хранения данных на физических носителях. Различные объекты одной базы данных, например, индекс и таблица, могут физически храниться в разных пространствах.

Ниже приведён краткий список преимуществ использования табличных пространств:

* Позволяют расширить текущие лимиты размера базы данных даже для небольших размеров таблицы.
* Даёт возможность контролировать использование базой данных доступного места и оптимизировать быстродействие. Например, пространство, используемое для индексов, можно разместить на быстрых накопителях, а неактивную или архивную части базы данных перемещать на медленные носители большого объёма.

[[fblangref-ddl-tablespace-create]]
== `CREATE TABLESPACE`

.Назначение
Создание нового табличного пространства.
(((CREATE TABLESPACE)))

.Доступно в
DSQL, ESQL

[[fblangref-ddl-db-create-syntax]]
.Синтаксис
[listing,subs="+quotes,attributes"]
----
CREATE TABLESPACE [IF NOT EXISTS] _ts_name_ FILE '_filepath_'
----

.Параметры оператора `CREATE TABLESPACE`
[[fblangref-ddl-tbl-create-tablespace]]
[cols="<1,<3", options="header",stripes="none"]
|===
^|Параметр
^|Описание

|ts_name
|Имя табличного пространства, может содержать до 63 символов.

|filepath
|Абсолютный или относительный (относительно первичного файла базы данных) путь к файлу табличного пространства.

|===

Оператор `CREATE TABLESPACE` создаёт новое пространство имён. Имя пространства имён должно подчиняться правилам для идентификаторов объектов базы данных и должно быть уникальным среди имён пространств имён. В качестве имени создаваемого пространства имён запрещено указывать имя `PRIMARY`, поскольку это имя зарезервировано для первичного пространства имён. Первичное пространство имён создаётся вместе с созданием базы данных. В текущей реализации разрешено создавать до 253 пользовательских пространств имён.

[NOTE]
====
Не рекомендуется также называть табличное пространство `TEMPORARY`, поскольку в будущих версиях табличное пространство с таким именем может стать предопределённым (для временных таблиц).
====

При создании табличного пространства можно указать либо абсолютный путь, либо относительный путь (относительно файла базы данных). При создании табличного пространства указанный файл не должен существовать — он будет создан в процессе.

Если используется предложение `IF NOT EXISTS`, то оператор `CREATE TABLESPACE` попытается создать новое табличное пространство без выдачи ошибки, если оно уже существует. DDL триггеры не будут запускаться, если табличное пространство уже существует.

[[fblangref-ddl-tablespace-create-who]]
=== Кто может создать табличное пространство?

Выполнить оператор `CREATE TABLESPACE` могут:

* <<fblangref-security-administrators,Администраторы>>;
* Пользователи с привилегией `CREATE TABLESPACE`.

Пользователь, создавший табличное пространство, становится его владельцем.

[[fblangref-ddl-tablespace-create-examples]]
=== Примеры

.Создание табличного пространства в Windows
[example]
====
[source,sql]
----
CREATE TABLESPACE BIG_TS FILE 'D:\fbdata\secondary.ts';
----
====

.Создание табличного пространства в Linux
[example]
====
[source,sql]
----
CREATE TABLESPACE BIG_TS FILE '/var/fbdata/secondary.ts';
----
====

.Создание табличного пространства, если его не существует
[example]
====
[source,sql]
----
CREATE TABLESPACE IF NOT EXISTS BIG_TS FILE 'D:\fbdata\secondary.ts';
----
====

[[fblangref-ddl-tablespace-alter]]
== `ALTER TABLESPACE`

.Назначение
Изменение существующего табличного пространства.
(((ALTER TABLESPACE)))

.Доступно в
DSQL, ESQL

[[fblangref-ddl-db-alter-syntax]]
.Синтаксис
[listing,subs="+quotes,attributes"]
----
ALTER TABLESPACE _ts_name_ SET FILE [TO] '_filepath_'

Подробнее см. в синтаксисе <<fblangref-ddl-tablespace-create-syntax,`CREATE TABLESPACE`>>
----

Оператор `ALTER TABLESPACE` позволяет изменить расположение файла для указанного табличного пространства. Если пространства имён с заданным именем не существует, то будет выдана ошибка. Эта операция не перемещает данные и не копирует файлы. Она применяется для изменения путей к табличным пространствам в случае их физического перемещения. Указанный абсолютный или относительный путь к файлу должен существовать.

[[fblangref-ddl-tablespace-alter-who]]
=== Кто может изменить табличное пространство?

Выполнить оператор `ALTER TABLESPACE` могут:

* <<fblangref-security-administrators,Администраторы>>;
* Владелец табличного пространства;
* Пользователи с привилегией `ALTER ANY TABLESPACE`.

[[fblangref-ddl-tablespace-alter-examples]]
=== Примеры

.Изменение пути табличного пространства
[example]
====
[source,sql]
----
ALTER TABLESPACE BIG_TS SET FILE TO '/var/fbts/secondary.ts';
----

Сам файл не перемещается, и его данные не копируются.
Этот файл был перемещён физически до выполнения этой команды.
====

[[fblangref-ddl-tablespace-createoralter]]
== `CREATE OR ALTER TABLESPACE`

.Назначение
Создание нового или изменение существующего табличного пространства.
(((CREATE OR ALTER TABLESPACE)))

.Доступно в
DSQL, ESQL

[[fblangref-ddl-tablespace-create-or-alter-syntax]]
.Синтаксис
[listing,subs="+quotes,attributes"]
----
CREATE OR ALTER TABLESPACE _ts_name_ FILE '_filepath_'

Подробнее см. в синтаксисе <<fblangref-ddl-tablespace-create-syntax,`CREATE TABLESPACE`>>
----

Оператор `CREATE OR ALTER TABLESPACE` создаёт новое табличное пространство, если его не существует, в противном случае изменяет расположение его файла.

См. также <<fblangref-ddl-tablespace-alter>>.

[[fblangref-ddl-tablespace-drop]]
== `DROP TABLESPACE`

.Назначение
Удаление табличного пространства.
(((DROP TABLESPACE)))

.Доступно в
DSQL, ESQL

[[fblangref-ddl-tablespace-drop-syntax]]
.Синтаксис
[listing,subs="+quotes,attributes"]
----
DROP TABLESPACE [IF EXISTS] _ts_name_

Подробнее см. в синтаксисе <<fblangref-ddl-tablespace-create-syntax,`CREATE TABLESPACE`>>
----

Оператор `DROP TABLESPACE` удаляет табличное пространство. Если в удаляемом табличном пространстве хранятся таблицы или индексы, то будет выдано сообщение об ошибке.

Если используется предложение `IF EXISTS`, то оператор `DROP TABLESPACE` попытается удалить табличное пространство без выдачи ошибки, если его не существует. DDL триггеры не будут запускаться, если табличного пространства не существует.

[[fblangref-ddl-tablespace-drop-who]]
=== Кто может удалить табличное пространство?

Выполнить оператор `DROP TABLESPACE` могут:

* <<fblangref-security-administrators,Администраторы>>;
* Владелец табличного пространства;
* Пользователи с привилегией `DROP ANY TABLESPACE`.

[[fblangref-ddl-tablespace-drop-examples]]
=== Примеры

.Удаление табличного пространства
[example]
====
[source,sql]
----
DROP TABLESPACE BIG_TS;
----
====

.Удаление табличного пространства, если оно существует
[example]
====
[source,sql]
----
DROP TABLESPACE IF EXISTS BIG_TS;
----
====
